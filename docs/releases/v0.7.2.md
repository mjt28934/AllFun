# AllFun 0.7.2

A compatibility patch. It fixes the crash that current Keiyoushi extensions hit when they
start: `java.lang.AbstractMethodError: abstract method
"kotlinx.serialization.KSerializer[] kotlinx.serialization.internal.GeneratedSerializer.typeParametersSerializers()"`.

Nothing in the interface changed: the same destinations, source states, reader, player,
library, downloads and marketplace. This release only moves the extension runtime forward so
modern extensions can run.

## What changed

- **kotlinx-serialization 1.7.3 → 1.13.0** (JSON and the Okio integration). Current
  extensions are compiled against 1.8+, where `GeneratedSerializer.typeParametersSerializers()`
  is a JVM default method. 1.7.3 declared it abstract, so a serializer that did not implement
  it crashed the moment the host built its descriptor. 1.13.0 is the version current Mihon
  ships, so extensions built for Mihon keep working.
- **Kotlin 2.2.21 → 2.4.21**, with the Compose and serialization compiler plugins. The
  extensions are built with Kotlin 2.4 metadata and need a matching stdlib.
- **AGP 8.7.3 → 8.13.2, KSP 2.3.14, Gradle 8.11.1 → 8.13** so the Kotlin 2.4 toolchain can
  build. `kotlinOptions` moved to the compiler-options DSL; `-Xjvm-default=enable` keeps the
  host interfaces emitting both real default methods and `DefaultImpls` bridges, which is
  what extension super calls expect.
- **kotlinx-coroutines 1.9.0 → 1.11.0** to match the same Kotlin line.
- OkHttp stays on 5.2.3, the newest 5.x that builds against this project's `compileSdk 35`.
  All extensions tested below work with it.

Older extensions keep working: new extensions rely on the interface's default method, and
older extensions still implement the method themselves, so both shapes are valid against the
new interface.

## Verified on the release build

- The crash is gone from logcat, and these current extensions load real content, not just
  their metadata: **Asura Scans** (Popular feed, search, details, chapters, 16-page reader),
  **MangaFire**, **Vortex Scans**, **Flame Comics** and **Drake Scans** (Popular feed, 190
  titles).
- An extension installed through the in-app Keiyoushi repository (download → signing-key
  check → register → load) works, so the normal install path is covered as well.
- **Comick (Unoriginal)** still cannot serve results here: comick.live answers with a
  Cloudflare challenge and the source reports `HTTP error 403`. That is the site blocking the
  request, not a serialization failure; every other source keeps working and the error is
  shown with the source name and Retry.
- `:app:testDebugUnitTest` passes 36/36, including new tests that fail the build if the
  serialization runtime ever loses the default method, plus round trips for generic,
  polymorphic, defaulted and unknown-field JSON.
- Signed release APK installed over 0.7.1 with the library, extensions, repositories and
  downloads kept.

## Install

1. Download `AllFun-0.7.2-release.apk` below.
2. Confirm the SHA-256 against `AllFun-0.7.2-release.apk.sha256`.
3. Open the file and let Android install it over 0.7.1. From inside the app, use
   **Settings → About → App Updates** instead.

Same certificate and package as every previous release, so your library, progress, settings,
extensions, repositories and downloads are kept.

## Notes

- Package remains `app.allfun`; `versionCode` 702, `versionName` 0.7.2.
- If an extension still fails, it is reported per source with its name and a Retry; other
  sources keep loading. A 403 usually means the site is challenging the request, not that the
  extension is incompatible.
