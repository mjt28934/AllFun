# AllFun 0.8.1

Two fixes and one rebuild: titles that came from a catalogue-only Stremio addon open on
their detail page instead of failing with "This provider returned a web page instead of
data", detail pages open as fast as a Library card and with the same animation, and the
download queue now behaves like Komikku's — an explicit persisted order, one pause for the
whole engine, and retries that belong to the transfer.

The library, progress, extensions, repositories and the 0.8.0 torrent player are unchanged.
Existing installations update in place.

## What changed

- **A catalogue addon is not asked for metadata.** Stremio addons declare which resources
  they serve. Streaming Catalogs declares only `catalog`, so asking it for `meta` returned an
  HTML page and every one of its titles failed on open. `SourceHub` now asks the origin
  addon only when its manifest declares `meta`, and fans out to every other installed video
  addon that declares `meta` and accepts the id — the same rule streams have used since
  0.8.0. Answers with `videos[]` win, the result is cached for five minutes, and the cache
  entry is dropped when the addon is removed.
- **Detail pages open at catalogue speed.** Tapping a card writes a preview row from the
  catalogue stub (title, cover, year, kind), navigates on that frame, and enriches the full
  metadata and episode list afterwards. The previous spinner that blocked navigation is
  gone. A stub can never wipe real episodes: an enrichment answer with no `videos[]` leaves
  the existing list alone. While the lookup is in flight the screen says it is looking for
  episodes instead of claiming the title has none.
- **One `meta` request per addon.** `StremioSource` serves both `details()` and `units()`
  from one bundle, so the fan-out costs one round trip per addon rather than two.
- **The queue has an order.** `queueOrder` is persisted in the database (a v5 → v6 migration
  adds it and backfills from `createdAt`); every query orders by it. New downloads append
  to the end of the queue, newest chapter first, and move-to-top, move-to-bottom, move whole
  title and the sort menu rewrite the same column. A restart restores the visible order.
- **Pause means pause.** The floating button pauses the whole engine: running transfers stop,
  the pause is saved, and nothing starts again until Resume — including after a restart.
  Resume requeues failed rows and continues from the same positions and partial files.
  Pausing a single item parks it the same way. Wi-Fi blocking is still a separate state and
  is never shown as "paused".
- **Retries belong to the transfer.** A failed request is retried three times with 2 s / 4 s
  / 8 s backoff before the row is marked failed; cancellation is never retried. Page images,
  chapter files and video files all use the same wrapper, so one flaky response no longer
  fails a whole chapter.
- **The queue header tells the truth.** Group summaries name what is actually happening
  (`2 downloading · 1 paused · 18%`, `1 waiting`, `3 saved`) and average only rows that
  reported a percentage, so a fresh queue entry cannot pin a title at 0%.

## Limits

- Drag-and-drop reordering is not in this release; move to top/bottom (per item and per
  title) and the sort menu cover the same job.
- Queue groups stay per title rather than per source. That is deliberate: "pause all for this
  title" then means what the user sees.
- Torrents still stream only; there is no offline torrent storage.

## Verified on the release build

- Signed 0.8.1 (`versionCode 801`, `versionName 0.8.1`, `CN=AllFun`) installed over 0.8.0
  with the library, extensions, sources and downloads kept.
- A local Stremio addon whose manifest advertises `resources: ["catalog"]` and answers every
  other endpoint with an HTML 404 was installed and browsed. Its shelf rendered, and tapping
  **The Matrix** opened the detail page with Cinemeta's title, year, genres, cast and video —
  no "returned a web page" error. The same title previously failed on that exact addon.
- Detail pages open without a blocking spinner: the screen appeared on the tap frame and
  filled in metadata, sources and episodes as the addons answered. A title with no `meta`
  provider keeps its catalogue stub instead of an error.
- Downloads queue on the same build: a running film, floating **Pause** → banner and every
  row **Paused** at 9% → **Resume** continued from 9%; sort menu reorders; move title to
  top/bottom; cancel all with confirmation removed partial files; clear finished deleted
  completed files; Wi-Fi-only rows show **Waiting for Wi-Fi**, not "paused"; delete files
  with confirmation.
- `:app:testDebugUnitTest` passes 54/54, including new `StremioManifestTest` cases (a
  catalogue-only addon is never asked for `meta`; type/prefix filtering) and
  `DownloadsQueueTest` cases (persisted order wins over creation time, both pause forms count
  as paused, grouping and progress). `:app:assembleDebug` and `:app:assembleRelease` succeed
  with R8 and resource shrinking.

## Install

1. Download `AllFun-0.8.1-release.apk` below.
2. Confirm the SHA-256 against `AllFun-0.8.1-release.apk.sha256`.
3. Open the file and let Android install it over 0.8.0. From inside the app, use
   **Settings → About → App Updates** instead.

Same certificate and package as every previous release, so your library, progress, settings,
extensions, repositories and downloads are kept.

## Notes

- Package remains `app.allfun`; `versionCode` 801, `versionName` 0.8.1.
- The APK is about 61.6 MB because it carries libtorrent for four ABIs.
- The database upgrade is a real migration, not a destructive reset: existing download rows
  are kept and receive their old creation order.
- A fresh install remains empty: no demo titles, no bundled content and no invented shelves.
