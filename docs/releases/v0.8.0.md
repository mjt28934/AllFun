# AllFun 0.8.0

Torrent-only Stremio addons play in-app. The player now asks every installed video addon
for a release, shows the alternatives it gets back, and plays a BitTorrent stream through
libtorrent instead of refusing it. Downloads has been rebuilt as a grouped queue with
per-title actions.

The library, progress, extensions, repositories and every existing source type are
unchanged. Existing installations update in place.

## What changed

- **Torrent playback.** A Stremio result with `infoHash` (or a magnet) is resolved by a
  real libtorrent session, which downloads pieces sequentially around the play position.
  The player reads the selected file through a Media3 `DataSource`, so seeking, subtitles
  and progress saving work exactly as they do for a direct stream. The engine stops when
  the player screen is left or another episode is opened.
- **Every addon is asked.** Streams are collected from all installed Stremio addons that
  accept the title's id, not only the addon that supplied the metadata. Torrentio and
  similar addons can now answer for Cinemeta's catalogues. A stream-only addon (no
  catalogs, but a `stream` resource) is accepted at install time, queried for streams, and
  hidden from category feeds instead of appearing as a broken catalogue.
- **Stream picker.** When more than one release comes back, the player lists them with the
  addon name, quality, seeds and size. Direct HTTP streams are listed first because they
  start instantly; torrents follow, ordered by quality (1080p/720p first) and then by
  advertised seeds. Duplicate infohashes are collapsed. A dead torrent offers **Choose
  another stream** rather than ending the session.
- **Buffering is visible.** Until the pieces around the start position are on disk the
  player shows the torrent's own state: percentage, peers and download speed.
- **Torrent downloads say what they are.** Streaming a torrent works; saving one for
  offline playback does not, and the download button now says so plainly instead of
  failing with a network error. Direct HTTP video still downloads to device storage.
- **Downloads queue, rebuilt.** `Settings → Downloads` now follows the Komikku layout: a
  back arrow, **Download queue** with a count of unfinished items, a sort menu (newest,
  oldest, title, progress) and an overflow menu for Wi-Fi-only and the concurrency limit.
  Items are grouped under their title with a summary line (`2 active · 18%`, `1 paused ·
  45.9 MB stored on this device`), per-group Pause all / Resume / Cancel / Delete, and a
  per-item menu. A floating **Resume** button appears whenever something is actually
  paused. The old flat sections are gone; the same records and files are used.

## Limits

- Torrents are streamed, not stored: there is no offline torrent download yet.
- Only one torrent plays at a time, and it stops when you leave the player.
- Addon results are capped at 60 alternatives per episode so the picker stays usable.
- A torrent with no reachable peers still fails; the message names that and offers the
  other releases returned for the same title.

## Install

1. Download `AllFun-0.8.0-release.apk` below.
2. Confirm the SHA-256 against `AllFun-0.8.0-release.apk.sha256`.
3. Open the file and let Android install it over 0.7.3. From inside the app, use
   **Settings → About → App Updates** instead.

Same certificate and package as every previous release, so your library, progress, settings,
extensions, repositories and downloads are kept.

## Notes

- Package remains `app.allfun`; `versionCode` 800, `versionName` 0.8.0.
- The APK is larger (about 61.6 MB) because it contains libtorrent for four ABIs
  (`arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`). All four are kept so the release works on
  devices and emulators alike.
- A fresh install remains empty: no demo titles, no bundled content and no invented shelves.
- Playing a torrent is the same legal position as playing any other addon result: AllFun
  ships no catalogue and only follows the addons the user installed.
